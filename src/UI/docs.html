登录与会话

未设置 --login 时，接口不要求 Cookie。设置密码后，先提交表单登录，再携带服务端返回的 ziger_session Cookie 调用 API。

curl -i -c cookie.txt \
  -X POST \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "password=123456" \
  http://localhost:8888/login/

curl -b cookie.txt \
  "http://localhost:8888/api/file-list/?path=."

登录成功返回 303 并跳转到 /。会话 Cookie 设置了 HttpOnly、SameSite=Strict，有效期为 30 分钟。

未登录访问受保护路由时返回 302，并重定向到 /login/。命令行客户端应保存并发送 Cookie，同时注意不要把登录页面误当作接口结果。

请求约定

  • JSON 接口使用请求头 Content-Type: application/json。
  • 路径相对于共享目录，根目录写作 .，子项目写作 fonts/readme.txt。
  • 不要使用空路径、绝对路径、./fonts、..、重复分隔符或盘符路径。
  • CurrentDir 可以是 .；具体文件项目的 Path 不能是 .。
  • 符号链接不会作为普通共享项目处理。

文件操作通常返回逐项结果数组：

[
  {"Path":"docs/readme.txt","Success":true,"Error":""},
  {"Path":"docs/missing.txt","Success":false,"Error":"source does not exist"}
]

GET/api/file-list/

查询指定目录。省略 path 时默认为共享根目录。

curl -b cookie.txt \
  "http://localhost:8888/api/file-list/?path=fonts"

响应：

[
  {
    "FileName":"readme.txt",
    "FileSize":"103 B",
    "FileIcon":"txt",
    "ModifiedTime":"2026-07-20 10:30:00"
  }
]

非根目录列表的第一项是用于返回上级的特殊项目 . .。

GET/api/share/{path}

读取文件或浏览目录。路径中的每个片段都应进行 URL 编码。

curl -b cookie.txt -OJ \
  "http://localhost:8888/api/share/fonts/readme.txt"

文件响应根据类型使用 inline 或 attachment；目录响应为简单 HTML 列表。不存在的文件返回 404。

WS/api/watch/

通过 WebSocket 监听共享目录变化。握手请求同样需要有效会话 Cookie。

const socket = new WebSocket("ws://localhost:8888/api/watch/");

socket.onmessage = event => {
  const message = JSON.parse(event.data);
  if (message.type === "changed") {
    console.log("共享目录已变化");
  }
};

目录发生变化时，服务端发送：

{"type":"changed"}

POST/api/file-property/

计算所选文件和目录的总数量、总大小及最近修改时间。

curl -b cookie.txt \
  -H "Content-Type: application/json" \
  -d '[{"Path":"fonts"},{"Path":"readme.txt"}]' \
  http://localhost:8888/api/file-property/
{
  "FileCount":4,
  "SumSize":"20.19 MB",
  "ModifiedTime":"2026-07-20 10:30:00",
  "AgoTime":"半小时前（星期一）"
}

公告板

POST/api/edit-announcement/

保存公告内容。该功能受 announcement 按钮开关控制。

curl -b cookie.txt \
  -H "Content-Type: application/json" \
  -d '{"Content":"今天 18:00 维护"}' \
  http://localhost:8888/api/edit-announcement/

POST/api/announcement-content/

读取当前公告，不需要请求体。

curl -b cookie.txt -X POST \
  http://localhost:8888/api/announcement-content/
{"Content":"今天 18:00 维护"}

POST/api/upload-file/

请求类型为 multipart/form-data。先发送一次 CurrentDir，随后为每个文件重复发送 RelativePath 和 File。

curl -b cookie.txt \
  -F "CurrentDir=docs" \
  -F "RelativePath=guide/readme.txt" \
  -F "File=@./readme.txt" \
  -F "RelativePath=images/logo.png" \
  -F "File=@./logo.png" \
  http://localhost:8888/api/upload-file/

RelativePath 决定目标相对路径，允许创建中间目录。目标已经存在时不会覆盖，并在逐项结果中返回失败。

当 --store 与 --share 不同时，文件保存到存储目录根位置，CurrentDir 不参与共享目录定位。

POST/api/search-file/

在选定文件或目录中搜索名称及可识别的文本内容。返回路径相对于 CurrentDir。搜索受服务器端深度、文件数、读取量和 3 秒时限保护。

curl -b cookie.txt \
  -H "Content-Type: application/json" \
  -d '{
    "Path":["docs","src/main.zig"],
    "Target":"router",
    "CurrentDir":".",
    "Limit":50,
    "Offset":0
  }' \
  http://localhost:8888/api/search-file/
{
  "Results":[{"Path":"src/main.zig","Description":"var router = try server.router(.{});"}],
  "NextOffset":null,
  "Truncated":false,
  "ScannedFiles":42
}

使用 NextOffset 作为下一次请求的 Offset 获取下一页；Truncated 为 true 时表示已达到扫描预算，需缩小范围或关键字后重试。

POST/api/delete-file/

删除一个或多个文件或目录。根目录 .、绝对路径和越界路径会被拒绝。

curl -b cookie.txt \
  -H "Content-Type: application/json" \
  -d '[{"Path":"temp/a.txt"},{"Path":"temp/old"}]' \
  http://localhost:8888/api/delete-file/

删除不可恢复，请始终检查 HTTP 状态和每个结果的 Success 字段。

POST/api/batch-download/

将所选项目写入 ZIP，并以 archive.zip 下载。每个所选项目都以自身 basename 作为归档根；目录内部结构会保留。

curl -b cookie.txt \
  -H "Content-Type: application/json" \
  -d '[{"Path":"project/app"},{"Path":"docs/readme.txt"}]' \
  -o archive.zip \
  http://localhost:8888/api/batch-download/

不同路径中 basename 相同的两个项目不能同时打包，否则返回 400 DuplicateArchiveName。请求中的 CurrentDir 不影响 ZIP 内结构。

POST/api/make-directory/

在已有的 CurrentDir 中创建一个目录。Path 是单个目录名称，不能包含 / 或 \。

curl -b cookie.txt \
  -H "Content-Type: application/json" \
  -d '{"Path":"images","CurrentDir":"docs"}' \
  http://localhost:8888/api/make-directory/
[
  {"Path":"images","Success":true,"Error":""}
]

复制与移动

POST/api/copy-file/

curl -b cookie.txt \
  -H "Content-Type: application/json" \
  -d '[
    {"Path":"docs/readme.txt","CurrentDir":"backup"},
    {"Path":"docs/images","CurrentDir":"backup"}
  ]' \
  http://localhost:8888/api/copy-file/

POST/api/move-file/

curl -b cookie.txt \
  -H "Content-Type: application/json" \
  -d '[{"Path":"incoming/report.pdf","CurrentDir":"docs"}]' \
  http://localhost:8888/api/move-file/

Path 是源项目，CurrentDir 是目标目录。目标已存在时，服务端自动使用 name (1).ext、name (2).ext 等可用名称，不覆盖已有项目。目录不能复制或移动到自身内部。

POST/api/rename-file/

单个或显式重命名

OldName 和 NewName 都是 CurrentDir 下的单个名称，不包含目录路径。

curl -b cookie.txt \
  -H "Content-Type: application/json" \
  -d '[{
    "CurrentDir":"fonts",
    "OldName":"readme.txt",
    "NewName":"README.md",
    "Prefix":"",
    "Suffix":""
  }]' \
  http://localhost:8888/api/rename-file/

批量重命名

批量模式下所有项目的 NewName 必须为空。新名称按照请求数组顺序生成；文件保留原扩展名，目录不追加扩展名。

curl -b cookie.txt \
  -H "Content-Type: application/json" \
  -d '[
    {"CurrentDir":"photos","OldName":"a.jpg","NewName":"","Prefix":"图片","Suffix":"号"},
    {"CurrentDir":"photos","OldName":"b.jpg","NewName":"","Prefix":"图片","Suffix":"号"}
  ]' \
  http://localhost:8888/api/rename-file/

结果名称为 图片1号.jpg 和 图片2号.jpg。同一请求不能混合显式名称模式与批量前后缀模式；目标存在时不会覆盖。

HTTP 状态码

状态含义
200请求成功，文件操作全部成功
207批量文件操作部分成功、部分失败
302未登录，重定向到登录页
303登录成功，跳转到首页
400JSON、路径、WebSocket 握手或请求参数无效
401登录密码错误
403对应功能被 --button 配置禁用
404文件或页面不存在
409全部文件操作失败，通常是目标冲突或操作失败
413上传或公告请求体超过配置限制
500存储、归档或服务器内部错误
